# Удаление_открытая_адресация

Операция удаления записи по заданному ключу в хеш-таблице с открытой адресацией. В отличие от таблицы с цепочками, ячейку нельзя просто очистить — это разорвёт цепочку проб и сделает часть элементов недостижимыми при последующем поиске. Вместо этого ячейка помечается специальным флагом `DELETED`.

## Алгоритм
1. Найти индекс `pos` в массиве, используя процедуру поиска (см. [[Поиск_открытая_адресация]]). Если ключ не найден — удаление невозможно.
2. Присвоить ячейке `T[pos]` состояние `DELETED` (например, специальное значение ключа).
3. Уменьшить счётчик хранимых элементов `n` на 1.

## Важные замечания
- Ячейки, помеченные `DELETED`, могут быть переиспользованы при вставке, но игнорируются при поиске.
- При большом количестве удалённых ячеек эффективность поиска падает (растёт средняя длина пробы). В таких случаях применяют перехеширование всей таблицы.

## Временная сложность
- В среднем совпадает с трудоёмкостью поиска: ожидаемое число проб $\frac{1}{1-\alpha}$.
- В худшем случае $O(m)$, где $m$ — размер таблицы.

## Реализация на Си
```c
#define EMPTY   -1
#define DELETED -2

int hash_delete(OpenAddrHashTable *ht, int key) {
    int idx = -1;
    for (int i = 0; i < ht->m; i++) {
        int cur = (key % ht->m + i) % ht->m;  // линейное пробирование
        if (ht->T[cur].key == EMPTY)
            return 0;          // ключ не найден
        if (ht->T[cur].key == key) {
            idx = cur;
            break;
        }
    }
    if (idx == -1) return 0;   // не найден (таблица полна, но ключа нет)
    ht->T[idx].key = DELETED;
    ht->n--;
    return 1;
}
```

# Бинарное_дерево_поиска

Динамическая структура данных, организующая элементы в виде двоичного дерева с инвариантом упорядоченности: для любого узла `x` все ключи в левом поддереве меньше `x->key`, а в правом — больше. Обеспечивает эффективную реализацию таблицы (словаря).

## Инвариант и свойства
- Дерево является **бинарным деревом поиска (BST)**.
- Симметричный (in-order) обход возвращает элементы в возрастающем порядке (см. [[Симметричный_обход]]).
- Операции поиска, вставки и удаления используют бинарный поиск по дереву.
- Высота $h$ дерева определяет время операций: в сбалансированном BST $h = O(\log n)$, в вырожденном $h = O(n)$.

## Основные операции
- [[Поиск_в_BST]]
- [[Поиск_минимума_BST]], [[Поиск_максимума_BST]]
- [[Поиск_предшественника_BST]], [[Поиск_преемника_BST]]
- [[Вставка_в_BST]]
- [[Удаление_из_BST]]

## Реализация на Си
Определение узла и проверка свойства BST (проверка, что дерево действительно является BST).

```c
typedef struct Node {
    int key;
    struct Node *left, *right;
} Node;

// Проверка: все ключи в поддереве [min, max]
int is_bst_util(Node *root, int min, int max) {
    if (!root) return 1;
    if (root->key <= min || root->key >= max) return 0;
    return is_bst_util(root->left, min, root->key) &&
           is_bst_util(root->right, root->key, max);
}

int is_bst(Node *root) {
    return is_bst_util(root, INT_MIN, INT_MAX);
}
```

# Поиск_в_BST

Алгоритм поиска заданного ключа в бинарном дереве поиска, использующий свойство упорядоченности: ключи в левом поддереве меньше, в правом — больше, чем ключ текущего узла.

## Алгоритм
Начиная с корня, сравниваем искомый ключ `k` с ключом узла:
- если `k == node->key` — узел найден;
- если `k < node->key` — переходим в левое поддерево;
- если `k > node->key` — переходим в правое поддерево.

Если достигнут `NULL`, ключ отсутствует.

## Временная сложность
- В сбалансированном BST: $O(\log n)$.
- В худшем случае (дерево вырождено в цепочку): $O(n)$.

## Реализация на Си
```c
Node* search_bst(Node *root, int key) {
    Node *cur = root;
    while (cur != NULL) {
        if (key == cur->key)
            return cur;
        else if (key < cur->key)
            cur = cur->left;
        else
            cur = cur->right;
    }
    return NULL;
}
```

# Эффективность_BST

Анализ временной сложности основных операций (поиск, вставка, удаление, минимум/максимум, предшественник/преемник) в бинарном дереве поиска. Все они выполняются за время, пропорциональное высоте дерева $h$.

## Зависимость от формы дерева
- **Сбалансированное BST** (высота $h = \Theta(\log n)$): каждая операция $O(\log n)$.
- **Вырожденное BST** (элементы вставлены в возрастающем/убывающем порядке, дерево — цепочка): $h = n-1$, операции $O(n)$.
- **Случайное BST** (равновероятные перестановки при вставке): средняя высота $\approx 2\ln n$, среднее время операций $O(\log n)$.

## Амортизационный анализ
Без балансировки дерево не гарантирует логарифмической глубины. Для получения гарантированной производительности используют самобалансирующиеся деревья (AVL, красно-чёрные), где после вставки/удаления выполняются локальные восстановительные операции, сохраняющие $h = O(\log n)$. Детали балансировок вынесены в отдельные заметки по каждому типу дерева.

# Поворот_правый

Локальная операция перестроения двоичного дерева поиска, которая изменяет структуру узлов, сохраняя инвариант BST. Правый поворот вокруг узла `x` выполняется при условии, что `x` имеет левого потомка `y`.

## Действие поворота
- `y` становится корнем поддерева на месте `x`.
- `x` становится правым потомком `y`.
- Бывшее правое поддерево `y` (`y->right`) становится левым поддеревом `x`.

## Применение
Правый и левый повороты — базовые операции для балансировки деревьев (AVL, красно-чёрное). Они выполняются за время $O(1)$, меняя лишь несколько указателей.

## Реализация на Си
```c
// x – указатель на указатель на узел, чтобы изменить связь с родителем
void rotate_right(Node **x) {
    Node *y = (*x)->left;
    if (!y) return;               // поворот невозможен
    (*x)->left = y->right;
    y->right = *x;
    *x = y;                       // новый корень поддерева
}
```

# Свойства_AVL

AVL-дерево — самобалансирующееся двоичное дерево поиска, в котором для каждого узла **фактор баланса** (разность высот левого и правого поддеревьев) по модулю не превышает $1$:
$$ \text{balance}(v) = \text{height}(v.\text{left}) - \text{height}(v.\text{right}) \in \{-1, 0, 1\} $$

## Гарантированная высота
Из условия баланса следует, что высота AVL-дерева с $n$ узлами не превышает $1.44 \log_2 n$. Поэтому время поиска, вставки и удаления составляет $O(\log n)$ в худшем случае.

## Реализация на Си
Структура узла с явным хранением высоты поддерева:
```c
typedef struct AVLNode {
    int key;
    struct AVLNode *left, *right;
    int height;
} AVLNode;

int get_height(AVLNode *v) {
    return v ? v->height : 0;
}

void update_height(AVLNode *v) {
    int hl = get_height(v->left);
    int hr = get_height(v->right);
    v->height = (hl > hr ? hl : hr) + 1;
}

int balance_factor(AVLNode *v) {
    return get_height(v->left) - get_height(v->right);
}
```

При вставке и удалении баланс может нарушиться; восстановление выполняется серией поворотов (см. [[Балансировка_AVL_после_вставки]], [[Балансировка_AVL_после_удаления]]).

# Поиск_B

Алгоритм поиска заданного ключа в B-дереве — сильно ветвящемся сбалансированном дереве поиска. Каждый узел содержит упорядоченный массив ключей и массив указателей на потомков (на один больше числа ключей).

## Алгоритм
1. Начиная с корня, для текущего узла `x` линейным (или бинарным) поиском находим позицию `i`, где должен находиться ключ `k` среди ключей узла.
2. Если $i \le \text{num\_keys}$ и `x->keys[i] == k`, поиск завершён успешно.
3. Если узел листовой (`x->leaf == 1`) — ключ отсутствует.
4. Иначе рекурсивно продолжаем поиск в дочернем узле `x->children[i]`.

## Временная сложность
$O(t \log_t n)$, где $t$ — минимальная степень дерева (размер узла между $t-1$ и $2t-1$ ключей). На практике глубина мала, а поиск в узле выполняется быстро.

## Реализация на Си
```c
typedef struct BTreeNode {
    int *keys;           // массив ключей
    struct BTreeNode **children; // массив дочерних узлов
    int num_keys;
    int leaf;            // 1 – лист
} BTreeNode;

// Возвращает индекс ключа в узле, либо -1
int btree_search_key_in_node(BTreeNode *x, int k) {
    for (int i = 0; i < x->num_keys; i++)
        if (x->keys[i] == k)
            return i;
    return -1;
}

// Поиск по всему дереву, возвращает узел или NULL
BTreeNode* btree_search(BTreeNode *root, int k) {
    BTreeNode *cur = root;
    while (cur) {
        int i = 0;
        while (i < cur->num_keys && k > cur->keys[i])
            i++;
        if (i < cur->num_keys && cur->keys[i] == k)
            return cur;
        if (cur->leaf)
            return NULL;
        cur = cur->children[i];
    }
    return NULL;
}
```

# Вставка_приоритетная_очередь

Операция добавления нового элемента в очередь с приоритетом. В большинстве реализаций очередь с приоритетом строится на базе **двоичной кучи** (бинарной heap), которая обеспечивает логарифмическое время вставки.

## Алгоритм (для max-heap)
1. Поместить новый элемент в конец внутреннего массива кучи (последний лист).
2. Выполнить **просеивание вверх** (sift-up): пока ключ элемента больше ключа его родителя, обменять их и подняться выше.
3. После завершения снова выполняется свойство кучи (родитель больше потомков).

## Временная сложность
$O(\log n)$, так как высота двоичной кучи $\lfloor \log_2 n \rfloor$.

## Реализация на Си
```c
typedef struct {
    int *data;
    int size;
    int capacity;
} PriorityQueue;

void swap(int *a, int *b) { int t = *a; *a = *b; *b = t; }

void insert(PriorityQueue *pq, int key) {
    if (pq->size == pq->capacity) return; // нет места
    pq->data[pq->size] = key;
    int i = pq->size;
    pq->size++;

    // sift-up
    while (i > 0 && pq->data[i] > pq->data[(i - 1) / 2]) {
        swap(&pq->data[i], &pq->data[(i - 1) / 2]);
        i = (i - 1) / 2;
    }
}
```

# Список_с_пропусками

Вероятностная структура данных, реализующая упорядоченное множество (словарь) с операциями поиска, вставки и удаления за $O(\log n)$ среднего времени. Состоит из нескольких уровней связных списков.

## Структура
- Самый нижний уровень (уровень 0) содержит все элементы в отсортированном порядке.
- Каждый более высокий уровень действует как «экспресс-линия» и включает подмножество элементов предыдущего уровня. Принадлежность элемента уровню $l$ определяется случайным образом (например, подбрасыванием монетки).
- Каждый узел хранит массив указателей `forward` длиной, равной его уровню.

## Операции
Операции поиска, вставки и удаления аналогичны пошаговому спуску по уровням, начиная с самого высокого, с продвижением вперёд или вниз. Детали реализации в отдельных заметках:
- [[Поиск_skip_list]]
- [[Вставка_skip_list]]
- [[Удаление_skip_list]]

## Реализация на Си (узел)
```c
typedef struct SkipNode {
    int key;
    int value;
    struct SkipNode **forward; // массив указателей на следующие узлы по уровням
    int level;                 // количество уровней узла (индексация с 0)
} SkipNode;
```

# Список_смежности

Представление графа $G = (V, E)$, при котором для каждой вершины $v \in V$ хранится коллекция смежных с ней вершин. Наиболее распространённая реализация — массив динамических списков, где индекс в массиве соответствует номеру вершины, а список содержит все вершины, соединённые ребром с данной.

## Свойства
- **Память**: $O(V + E)$ для хранения всего графа, что делает его предпочтительным для разреженных графов.
- **Перебор соседей**: за время $O(\text{degree}(v))$.
- **Проверка наличия ребра** $(u, v)$: $O(\text{degree}(u))$ без дополнительных структур.

## Реализация на Си
Вариант с динамическими массивами для списков:
```c
typedef struct {
    int *adj;    // массив соседей
    int size;
    int cap;
} AdjList;

typedef struct {
    AdjList *vertices; // массив списков по числу вершин
    int V;
    int E;
} Graph;

// Добавление ориентированного ребра u -> v
void add_edge(Graph *g, int u, int v) {
    AdjList *list = &g->vertices[u];
    if (list->size == list->cap) { /* перевыделение памяти... */ }
    list->adj[list->size++] = v;
}
```
Для неориентированного графа ребро добавляется и в `vertices[v]`.
