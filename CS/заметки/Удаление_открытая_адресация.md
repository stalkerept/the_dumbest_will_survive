
Операция удаления записи по заданному ключу в хеш-таблице с открытой адресацией. В отличие от таблицы с цепочками, ячейку нельзя просто очистить — это разорвёт цепочку проб и сделает часть элементов недостижимыми при последующем поиске. Вместо этого ячейка помечается специальным флагом `DELETED`.

## Алгоритм
1. Найти индекс `pos` в массиве, используя процедуру поиска (см. [[Поиск_открытая_адресация]]). Если ключ не найден — удаление невозможно.
2. Присвоить ячейке `T[pos]` состояние `DELETED` (например, специальное значение ключа).
3. Уменьшить счётчик хранимых элементов `n` на 1.

## Важные замечания
- Ячейки, помеченные `DELETED`, могут быть переиспользованы при вставке, но игнорируются при поиске.
- При большом количестве удалённых ячеек эффективность поиска падает (растёт средняя длина пробы). В таких случаях применяют перехеширование всей таблицы.

## Временная сложность
- В среднем совпадает с трудоёмкостью поиска: ожидаемое число проб $\frac{1}{1-\alpha}$.
- В худшем случае $O(m)$, где $m$ — размер таблицы.

## Реализация на Си
```c
#define EMPTY   -1
#define DELETED -2

int hash_delete(OpenAddrHashTable *ht, int key) {
    int idx = -1;
    for (int i = 0; i < ht->m; i++) {
        int cur = (key % ht->m + i) % ht->m;  // линейное пробирование
        if (ht->T[cur].key == EMPTY)
            return 0;          // ключ не найден
        if (ht->T[cur].key == key) {
            idx = cur;
            break;
        }
    }
    if (idx == -1) return 0;   // не найден (таблица полна, но ключа нет)
    ht->T[idx].key = DELETED;
    ht->n--;
    return 1;
}
```
