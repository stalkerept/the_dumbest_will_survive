
Алгоритм поиска записи по ключу в хеш-таблице с открытой адресацией. Основан на последовательном просмотре проб, начиная с начального хеша, до обнаружения искомого ключа или пустой ячейки.

## Алгоритм
1. Вычислить $i = 0$, начальный индекс $idx = h(k, 0)$.
2. Если $T[idx].key = k$, вернуть найденную запись (или её индекс).
3. Если $T[idx]$ — `EMPTY` (никогда не содержала элемента), поиск завершается неудачей: ключа нет.
4. Если $T[idx]$ — `DELETED`, перейти к следующей пробе.
5. Иначе ячейка занята другим ключом — перейти к $i = i+1$, вычислить следующий $idx = h(k,i)$ и повторить с шага 2, пока $i < m$. Если пройдены все $m$ проб, таблица полностью заполнена (или ключ не найден).

## Временная сложность
В среднем, при равномерном хешировании и $\alpha < 1$, ожидаемое число проб:
$$ \frac{1}{1-\alpha} $$
В худшем случае — $O(m)$, если все пробные цепочки длинны.

## Реализация на Си
```c
// Возвращает индекс найденной записи или -1 при отсутствии.
int hash_search(OpenAddrHashTable *ht, int key) {
    for (int i = 0; i < ht->m; i++) {
        int idx = (key % ht->m + i) % ht->m;  // линейное пробирование
        if (ht->T[idx].key == EMPTY)
            return -1;          // точно отсутствует
        if (ht->T[idx].key == key)
            return idx;         // найден
        // если DELETED — продолжаем поиск
    }
    return -1; // обошли всю таблицу, ключ не найден
}
```
При других стратегиях пробирования достаточно заменить формулу вычисления `idx`.
